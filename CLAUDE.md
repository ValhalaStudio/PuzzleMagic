# PuzzleMagic: notes for whoever (or whatever Claude session) works on this next

UE 5.8 C++ game (module `PuzzleGame5x5`), a Halloween block puzzle where tiles are skeleton hands pointing at a neighbour and you
build **routes**. The UI is built in C++ (UMG, no Widget Blueprints). Read `README.md` for the full feature list and
`Architecture.html` (generated by `Tools/ArchitectureDoc/gen_architecture.py`, re-run it after adding types or scripts) for the code map.

## Working agreements
- The designer wants to see each change working (screenshots) before it is committed. Commit only when asked; push only to the
  fork `fork` (`areklis/PuzzleMagic`). The upstream `origin` (ValhalaStudio) is never pushed to.
- Never run two builds at once, and never a build while the editor or a game is open (corrupts `Intermediate`).
- After testing on a phone or tablet, close the game (`adb shell am force-stop com.valhallastudios.puzzlemagic`) and leave the
  device's settings as found. Never screenshot a whole PC desktop; capture only the game window.

## Rules (as implemented; the designer confirmed them)
- A route is a chain of tiles, each hand pointing at the next. It must **start** on an edge tile pointing straight away from the
  side it touches and **end** on an edge tile pointing straight out of an edge. A chain that leaves through the side it started
  from is a closed circuit, a "Trick": scores nothing, costs one combo step. Only the chain's tiles clear.
- Score: 10 per route + 2 per tile; routes that share a tile earn +5 per route cleared together; combo ("TREAT xN") multiplies
  route points. Pumpkin 25, bottle 50, each +2 per chain tile, linked full-to-empty potion pair 100.
- Bonus tiles (Play options): a pumpkin every 200 points, a potion pair every 600; they spawn on non-scoring cells and never into
  a game over. Relics (Holy Light 3x3 purge, Reroll the tray) are earned every 3 combo steps and cost luck.
- Board 4..8 by 4..8 (the Play options and the campaign steps choose it). Coordinates: x=0 is the left column, y=0 the bottom row.

## Campaigns (arcade and tutorial)
Data, not code: `Content/Campaigns/arcade.json` and `tutorial.json` (the game also reads `<game>/Campaigns/` first, so a file dropped
there is tried without a rebuild). Edit them with `Tools/CampaignEditor/campaign_editor.html` (single file, open it in a browser).
A step sets goal score and/or routes, time limit, board size, relics with starting charges, bonus tiles, hold slot on/off,
intro/outro/hint text, pre-placed tiles, and a curated tray (buckets of pieces dealt in order; separate reroll buckets; "win when
every bucket is used up"). Code: `CampaignData.*` (parsing), `PuzzleArcade.cpp` (flow), GridManager curated-tray functions.

## Platforms and the lightweight mode
- Phones/tablets always run the lightweight scene (`PuzzleLite::IsLite()`): pre-rendered backdrop + sprite bats/steam, no
  post-process (they do not compile for the mobile renderer and the engine paints a grey grid over everything). PC "Low graphics"
  (Play options) uses the same scene. Capped at 30 fps with an adaptive 3D resolution (measured about 22% less power than uncapped).
- The scenery pictures sit at depths that scale with the camera distance; a fixed depth once hid the board on a 20:9 phone.
- Android Orientation must be the plain name (`Orientation=Sensor`); the `EAndroidScreenOrientation::` form silently becomes landscape.
  The options card has a Landscape/Portrait toggle (saved). `bUseExternalFilesDir=True` is needed for saves on Android 11+.
- Themes (Play options THEME button, saved, `-theme=desk|halloween|classic`): a table in `PuzzleStyle.h` (`FPuzzleThemeDef`), one entry per
  theme. Desk (default): plain triangle tiles, graphite board, `ADeskEnvironment` (wood desk, mug, pencil, notebook; real geometry, so no
  backdrop picture even in the lightweight mode). Halloween: skeleton hands, potions, cauldrons, bats, streams in the cathedral. Classic: the
  pre-Halloween triangle tiles in the cathedral without props (`T_LiteBackdropClassic`). Changing theme reloads the map. To add a theme:
  an `EPuzzleTheme` value, a table entry, and its scenery/materials (`Tools/build_desk_materials.py` is the pattern); `PuzzleUiCard theme` cycles it.
- Card titles shrink to fit the frame and long text wraps in a 640-unit box: wrapped text draws about 15% wider than its box.

## The demo build (Demo 1 / Demo 2)
Same code, trimmed, switched on by `PuzzleDemo.h`: a `DemoBuild.txt` next to the packaged game, `-demobuild`, or `PUZZLE_DEMO=1` at build time
(the demo APK). Menu: DEMO 1 (4x4, no bonus tiles, ends at 4000), DEMO 2 (7x7, bonus tiles, ends at 6000), TUTORIAL, PLAY OPTIONS, EXIT; Desk
theme only; each mode keeps its own best. `-captest` (dev) brute-forces the cap with `Content/Campaigns/captest.json`. Greek text is picked from
the system language (`PuzzleLocale.h`, `Content/Localization/el.json`, `tutorial_el.json`). Windows: `build_packages.ps1 -Demo` (Shipping,
branded launcher that keeps saves in the game folder). Android: `-DemoApk` (Shipping; `PuzzleDemo_UPL.xml` drops the network/billing
permissions). `-DemoDev` builds the same demo as a Development APK. The script clears an Android configuration when it flips between demo and
full game: UnrealBuildTool does not see `PUZZLE_DEMO` change and would reuse the other kind's library. The demo tune `MUS_Demo` is not in the
repository (licence): run `Tools/import_demo_music.py <mp3>` in the editor; without it the demo plays the organ piece only.

## Workflows (project skills in `.claude/skills/`, usable in any Claude Code session here)
- `build-test-packages`: compile and build the Windows zip and the Android APK (`Tools/build_packages.ps1`, `Tools/package_windows.py`).
- `device-test`: UI sweep, soak, frame rate and power tests on real phones/tablets (`Tools/AndroidTests/`, paths and devices are
  discovered; `PM_BUILDS`, `PM_APK`, `PM_OUT`, `PM_DEVICE` override). Includes the rules that cost hours to learn.
- `ui-overlap-check`: text and buttons must stay inside the cards on every screen shape.
- `ship-changes`: commit, push to your fork, and prepare a pull request.

## Build and test facts
- Compile only: `Build.bat PuzzleGame5x5Editor Win64 Development -Project=...\PuzzleGame5x5.uproject -WaitMutex`.
- The Android cook sometimes dies at teardown with an engine ensure after printing "Done!": just retry. Zip with forward slashes.
- Material scripts (`Tools/*.py`) run through `UnrealEditor-Cmd -run=pythonscript` with the editor closed.
- Debug commands on a test build: `adb shell setprop debug.puzzle.exec '<console command>'` runs once per distinct text and again at
  every launch (clear it with `''`). Game commands: `PuzzleUiCard`, `PuzzlePerf`, `PuzzleHide`, `PuzzleArcadeTest`.
- A secure lock screen cannot be opened by adb. Power can only be measured unplugged (use the battery charge counter).
